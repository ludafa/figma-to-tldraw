# 提交流程

每次 `git commit`，husky 的 `commit-msg` 钩子都会用 commitlint 检查提交信息，不符合 Conventional Commits（`type(scope): subject`）就拦下。`pnpm install` 之后钩子自动生效，不用手动 `husky init`。让 Claude 提交时用 `/commit`（只提交已暂存的改动）或 `/split-commits`（把一堆改动拆成多个提交）。仓库的三个包都是不发布的应用，所以没有 changesets，提交信息只影响历史好不好读，不决定版本号。

## 关键决定

- 只做"提交工作流"，不引入 changesets、不建 `/release`：没有要发布的包（用户在两个选项里选的，2026-07-19，见 [tech.md §1](tech.md#1-选型2026-07-19)）
- 装 commitlint + husky 做机器兜底（用户选择安装，见 [tech.md §2](tech.md#2-钩子与配置2026-07-192026-10-22-修订)）
- 删掉 `husky init` 生成的 `pnpm test` pre-commit 钩子：每次提交跑全量测试太重。2026-10-22 加回的 pre-commit 只格式化暂存文件，不跑测试（见 [tech.md §2](tech.md#2-钩子与配置2026-07-192026-10-22-修订)、[lint-format](../lint-format/README.md)）
- 提交信息不加 "Generated by Claude"、co-author 之类的尾注，不用 `--no-verify` 绕过钩子（见 CLAUDE.md「Git 提交约定」和 [tech.md §3](tech.md#3-slash-command2026-07-19)）
