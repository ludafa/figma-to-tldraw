# 自研 Skia 画面引擎：产品设计

> 相关：[模块说明](README.md) · [技术实现](tech.md) · [施工计划](plan.md) · [验证方案](verification.md)

## 1. 要解决的问题（2026-10-27）

现在的 Demo 把 Figma 节点变成 tldraw 图形，用 HTML、CSS 和 SVG 画。还原度已经不错（175 个用例平均差异 0.0961%，174 个小于 1%，`reports/fidelity/20261026-015324/`），但有两类问题绕不过去：

- **画法受浏览器限制。** 组透明度、背景模糊、混合模式只能用裁剪和叠层去凑（tldraw 版 tech.md §5、§6.3、§12.6），浏览器的文字基线取整和 Figma 不同，要按字号逐个补偏移（tldraw 版 tech.md §6.4）。
- **性能随节点数下降。** 每个节点都是一个 DOM 元素，大稿子（1468 个节点的 golio 落地页）平移和缩放时浏览器要重新合成上千个层。

所以换成自己写的引擎：数据和交互照搬 tldraw 的用法，画面用 Skia 在一张 WebGL 画布上画，Figma 的每种效果直接翻成 Skia 的绘制命令。

## 2. 用户看到什么（2026-10-27）

- 页面和入口不变：`/canvas`、`/showcase`、`/how-it-works`、`/report`、`/import` 都还在，地址参数（`?case=`、`?shot=1`、`?select=`）不变。
- 画布从 tldraw 的 DOM 换成一张 `<canvas>`。左栏的用例列表、图层树，右侧的属性面板，顶部的叠加对比条照旧是 React 界面，盖在画布上面。
- 编辑功能保持原样：选择（Figma 式的先选最外层、双击进入）、缩放旋转、自动布局里拖动排序、对齐线、新建 Frame / 矩形 / 椭圆 / 文字、改文字、组件实例、撤销重做、复制粘贴、快捷键。
- 选框、控制点、悬停描边、框选矩形、对齐线用 Skia 画在画面最上层，样式用 Figma 的蓝色。
- 工具栏照旧是选择、抓手、Figma 的 4 个新建工具，加上画笔、箭头（tldraw 版用户定的保留项，`figma/editing/tools.tsx` 的 `KEPT_TOOLS`）；画笔、箭头换成本引擎自己的简化版（§5）。

> 2026-10-27 修订：原来写的是“画笔、箭头去掉”。后来发现 tldraw 版保留这两个工具是用户定的，不能悄悄删，改成自己实现简化版。

## 3. 还原度目标（2026-10-27，用户拍板）

**用当前 175 个用例测，每个用例和 Figma 导出的 2 倍图相比，差异都小于 1%**（差异 = 不同像素 ÷ 总像素，pixelmatch 阈值 0.1，和原来的对比脚本一样）。tldraw 版只有 `real/50-landing-page-designs-community/designs-48` 超过（1.237%），换引擎以后不能有用例变差到 1% 以上。

## 4. 性能目标（2026-10-27，用户拍板）

下面 4 项操作，在用例上测，帧率都不低于 60fps：

1. **平移视野**：按住空格或中键拖动、触控板双指滑动。
2. **缩放视野**：按住 Ctrl / ⌘ 滚轮、触控板捏合。
3. **自由布局里拖动节点**：拖一个不在自动布局容器里的图层。
4. **自动布局容器里拖动排序**：拖一个自动布局的子节点，经过兄弟节点时实时交换位置（tldraw 版 tech.md §13.6）。

测法：用最大的几个用例（golio 落地页 1468 个节点、Untitled UI 的 600 多个节点的页面），脚本模拟操作 2 秒，记录每一帧的间隔，看平均帧率和最慢的 5% 帧。具体见 [verification.md §2](verification.md#2-端到端检查)。

## 5. 范围与非目标

**范围：** §2～§4。引擎 API 和 tldraw 保持一致（用户拍板），够现有代码用就行，不追求覆盖 tldraw 的全部 API。

**非目标：**

- tldraw 自带的几何图形、便签、文本、高亮等工具和它们的图形；画笔、箭头只做简化版（画笔：一条平滑的线，不做压感和闭合填充；箭头：直线加箭头，不做弯曲、绑定和标签）。
- tldraw 的菜单、工具栏、样式面板这套 UI（原来就没用，用的是自己的 `FigmaToolbar`、`FigmaStylePanel`）。
- 多人协作、`.tldr` 文件的完整兼容。`/import` 页的"下载 .tldr"照旧导出 tldraw 文件格式，但只保证结构对（见 [tech.md §3.5](tech.md#35-导出-tldrengineserializets2026-10-27)）。
- 动画相机（`zoomToBounds` 的 `animation` 参数接受但直接跳过去）。

## 6. 成功标准

1. `pnpm --filter @figma-to-tldraw/client compare` 跑完 175 个用例，报告里每个用例都小于 1%。
2. 性能基准脚本 4 项操作的平均帧率都 ≥ 60fps。
3. `apps/client/package.json` 里没有 `tldraw`，`grep -r "from 'tldraw'" apps/client/src` 没有结果。
4. `pnpm lint`、`pnpm typecheck`、`pnpm test` 全部通过；原来 `figma/` 下的测试都还在、都通过。
5. 在 `/canvas` 打开任一用例：能选中、拖动、缩放、改文字、在自动布局里拖动排序、撤销重做，表现和 tldraw 版一样。

## 7. 总览 Demo 页 `/demo`（2026-10-27，用户追加）

用户要一个"整体能看到"的 Demo 页面，放在 client 里，多放用例，画面里至少有 2 万个节点（用户追加）。

**看到什么：**

- 打开 `/demo`，一张画布上铺满 `cases/` 里的全部 175 个用例：87 个基础用例按类别（填充、描边、文字……）分块，6 套真实稿子各占一块。按 Figma 节点转出来的图形一共约 22100 个（实测，§7 末尾），超过 2 万。
- 打开后先缩放到能看到全部，用例按从小到大的顺序一个个加载出来（大的 golio 落地页最后），不用等全部加载完就能拖动、缩放。
- 每块上方有类别名，每个用例上方有用例名，字的大小不随缩放变；缩得太小、用例名会挤在一起时自动隐藏。点用例名缩放到这个用例。
- 左上角一个面板：加载进度、已加载的用例数和图形数、实时帧率，"看全部"按钮和类别列表（点了跳过去）。
- 画布和 `/canvas` 一样能编辑：选中、拖动、在自动布局里拖动排序、改文字、撤销重做（用的是同一套 Figma 编辑代码）。
- 地址参数 `?copies=N`（1～4，默认 1）把整面墙重复 N 份，用来压到 4 万、6 万个图形看性能；每份是独立的图形，可以分别编辑。

**非目标：** 不显示图层树（2 万多个图层的树没法看）；不做和 Figma 截图的叠加对比（每个用例的对比在 `/canvas` 和 `/showcase`）；不做"只加载看得见的用例"的懒加载，先全量加载。

**加载速度不在这次的范围里**：打开 `/demo` 到全部加载完约 13 秒（2026-10-28 实测），主要花在下载和解析快照 JSON（去掉主组件后还有 212MB）。现阶段可以接受，以后单独安排一章优化 JSON 体积，图片的预处理（生成几档缩略图）也放到那时一起做。这次的重点是还原度、画面的基本操作和性能（用户确认，2026-10-28）。

**成功标准：**

1. `/demo` 加载完后图形数 ≥ 20000，175 个用例都在。
2. 在这张画布上，平移、缩放、自由拖动、自动布局拖动排序 4 项操作平均帧率 ≥ 60fps（和 §4 同样的测法）。
3. 加载过程中页面能操作，不卡死。
