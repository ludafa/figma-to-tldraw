# Figma 还原到 tldraw

把 Figma 里的设计稿画到 tldraw 画布上，再和 Figma 自己导出的图片逐像素对比，算出还原度。**2026-10-27 起画布换成自研的 Skia 画面引擎**（API 和 tldraw 一样，见 [自研 Skia 画面引擎](../skia-engine/README.md)），下面讲的转换、插件、对比、编辑和组件都照旧，"怎么画"的部分（§2、§3、§5、§6）改由 `figma/skia/` 来做，各章开头有修订说明。数据由自己写的 Figma 插件导出成 `cases/`（每个用例一份快照 JSON 加一张 Figma 渲染的 2 倍图）。每个 Figma 节点变成一个 tldraw 自定义图形，图形里用普通的 HTML、CSS 和 SVG 按 Figma 的样式画，不用 tldraw 自带的手绘风格图形。对比脚本用 Playwright 截图、pixelmatch 算差异，生成按差异排序的报告。

施工计划（todo 清单）在仓库根目录的 [`docs/施工计划.md`](../../../docs/施工计划.md)，交接时的原始材料在 [`docs/handoff/`](../../../docs/handoff/HANDOFF.md)。

## 关键决定

- 用 seed 项目 hono-mono-starter 做底座，tldraw 用 3.x 的最新版 3.15.6（用户拍板，2026-10-24）
- 每个 Figma 节点对应一个 tldraw 自定义图形，推翻了交接文档里"Demo 先整个 section 一个图形"的做法（用户拍板，2026-10-24，见 [tech.md §3](tech.md#3-自定义图形2026-10-24)）
- tldraw 3.x 只有自带的 `frame` 能裁剪子图形，所以裁剪和蒙版由子图形自己用 CSS `clip-path` 做（2026-10-24，见 [tech.md §2](tech.md#2-tldraw-3x-的限制2026-10-24) 和 [§5](tech.md#5-裁剪和蒙版2026-10-24)）
- Demo 结果：79 个用例平均差异 0.004%，全部小于 1%，65 个逐像素一致；已知限制和下一步见 [verification.md §5](verification.md#5-demo-结论2026-10-24)（2026-10-24）
- 用 Figma 社区的 31 个整页考了一次（不改规则）：只用 Inter 的 Untitled UI 24 页都在 0.17% 以下；Gemini 7 页平均 8.39%，原因是缺字体、First on top 叠放、图片滤镜、文字渐变，之后按特性修了叠放、Red Hat Display、文字渐变、图片滤镜四项，Product Sans 用开源的 Google Sans Flex 近似代替；最后 118 个用例平均 0.07%，全部小于 1%（2026-10-24，见 [verification.md §6](verification.md#6-真实稿子考试2026-10-24)）
- 图片滤镜不自己算，插件导出时让 Figma 渲染一份带滤镜的图（2026-10-24，见 [tech.md §6.8](tech.md#68-图片滤镜2026-10-24真实稿子考试补)）
- 展示页 `/showcase` 逐个用例放原稿链接、Figma 截图、可交互的 tldraw 画布和差异分析；差异分析里的"差异出在哪"由对比脚本把每个不同的像素归到盖在最上面的节点算出来（用户追加，2026-10-24，见 [tech.md §10](tech.md#10-展示页-showcase2026-10-24用户追加)）
- 思路介绍页 `/how-it-works` 用一页讲链路、关键做法、怎么量、怎么一步步变像，带一个节点树和 tldraw 图形互相选中的演示（用户追加，2026-10-24，见 [tech.md §11](tech.md#11-思路介绍页-how-it-works2026-10-24用户追加)）
- 真实稿子堆到 10 套（用户追加，2026-10-25）：又加了 8 套社区免费稿子（手机 App 和落地页，33 页），第一次跑平均 4.71%；按特性修了字体版本、长页面分段截图、水平翻转、只有描边的投影、U+2028、没有填充的背景模糊，33 页平均 0.38%、30 页小于 1%，剩下 3 页是 Social App 的商业字体；151 个用例平均 0.13%（见 [tech.md §12](tech.md#12-再加-8-套真实稿子2026-10-25用户追加) 和 [verification.md §7](verification.md#7-再加-8-套真实稿子2026-10-25)）
- 让图形在 tldraw 里能编辑：保留自定义图形，`props.node` 仍是唯一的数据来源，编辑就是改它；先做缩放和选择、自动布局、文字编辑、属性面板四步，矢量改颜色以后再做（用户拍板，2026-10-25，见 [probe-editing.md](probe-editing.md) 和 [tech.md §13](tech.md#13-在-tldraw-里编辑2026-10-25用户追加)）。自动布局自己写算法，整棵树重排 15644 个图层里 15620 个不动；文字用 tldraw 自带的 TipTap，3215 段文字来回转换完全一致；导入时的还原度不变
- 新建图层和图层树：新建 Frame、矩形、椭圆、文字的工具（矢量等第 5 步），tldraw 自带的工具只留画笔和箭头；左栏上面是用例列表、下面是和 Figma 一样的图层树，能选中、改名、隐藏、锁定；图层树里拖动排顺序、移进别的 frame 放到下一步（用户追加和拍板，2026-10-25，见 [tech.md §14](tech.md#14-新建图层和图层树2026-10-25用户追加)）
- 用例只用开源字体（`OPEN_FONTS`），用到商业字体的 21 个用例去掉，以后补用例也要避开（用户追加，2026-10-25，见 [tech.md §15](tech.md#15-只用开源字体的用例2026-10-25用户追加)）。130 个用例平均 0.0662%。2026-10-26 补了 45 个不用商业字体的新用例（用 `screencapture` + System Events 操作 Figma 桌面版导出，新装 Work Sans 等 5 种开源字体），顺带修了 Lato 斜体、Lato 300 / 900、有字间距时的连字、居中文字行尾空格四个文字问题：175 个用例平均 0.0961%，原来 130 个降到 0.0645%（见 [tech.md §15.1](tech.md#151-补新用例2026-10-26)）
- Figma 组件按调研的方案 A 做（用户让我中途拍板，2026-10-25，见 [tech.md §16](tech.md#16-figma-组件2026-10-25用户追加)）：插件把用到的主组件和整套组件集导进快照，导入时按主组件重建每个实例、补全覆盖记录，主组件放"组件"页；实例里的图层还是真实图形，改主组件时引擎把没覆盖的字段同步过去，实例里的改动记成覆盖；切变体、组件属性、重置、分离、新建组件、生成实例都在属性面板里
- 汇报页 `/report` 讲开源字体用例和组件这一轮：六件事的结果、实现思路、遇到的问题、效果和展示页的更新，里面两个例子点开才嵌入 `/canvas`，`/canvas?select=<节点 id>` 打开就选中那个图层（用户追加，2026-10-26，见 [tech.md §17](tech.md#17-汇报页-report2026-10-26用户追加)）
- 导入和对比页 `/import`：左边导入 zip、每次导入的分数和差异报告、图层树，中间画布，右边节点 inspector（用户追加，2026-10-26）。整个流程在浏览器里，数据存 IndexedDB，所以 Vercel 上也能用；截图用 modern-screenshot 并自己内嵌字体，真实页面的分数和 Playwright 一般只差零点几个百分点，背景模糊截不出来；插件导出和页面导入时都提醒商业字体会降低还原度（见 [tech.md §19](tech.md#19-导入和对比页-import2026-10-26用户追加)）
- 导入对比 Demo 页 `/compare`：导入插件导出的 zip（一个 section），我们的画布、Figma 截图、差异、差异分析四块，镜头一起动（用户追加，2026-10-28）。截图和差异两块不是画布，是跟着画布镜头重画的分块图片金字塔，3840×30640 的长图放大拖动也是 240fps；差异改成一条一条算，上限从 8000 万像素提到 1.6 亿。用真实 section 试出来 Figma 导出 section 的图四周多 40px（§9.7），修好后 22.55% → 0.21%（见 [tech.md §20](tech.md#20-导入对比-demo-页-compare2026-10-28用户追加)）
- 取数据用自己写的 Figma 插件，不用 REST API 和 MCP；Demo 阶段不做 WebSocket、写入 Figma、去默认值和性能优化（交接文档已定）
