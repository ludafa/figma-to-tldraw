# 调研：转出来的图形能不能在 tldraw 里编辑文字、形状和样式？

> 2026-10-25，tldraw 3.15.6，Node 26.12.1，macOS 27.0.1
> 起因：用户说「现在我需要调研找到一个方案，可以让我们转出来的 tldraw 节点，都可以在 tldraw 中编辑。不光是移动，还包括文本、形状、样式可以在 tldraw 中编辑。」
> 这份文档只回答可行性，不做设计。用户定了方向以后，设计写进 [技术实现](tech.md)，步骤写进[施工计划](plan.md)。

## 1. 结论

**能做，不用换 tldraw 版本，也不用推翻"每个节点一个自定义图形"。** 图形和画法都不动，Figma 的节点数据（`props.node`）仍然是唯一的数据来源，编辑就是改这份数据，画法照旧。在这个基础上补五块能力。最难的是自动布局，这一块用现有数据实测过，自己写的算法和 Figma 的结果一致。换成 tldraw 自带的图形不行，它们表达不了 Figma 的样式（§3.2）。

| 要编辑的         | tldraw 3.15.6 里现成的                                                 | 我们要补的                                                   | 可行性                                                                 |
| ---------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 移动、缩放、旋转 | `canResize`、`onResize`、`canResizeChildren`                           | 打开开关；frame 缩放时按 Figma 的约束（constraints）摆子图层 | ✅ 查源码（§3.3）                                                      |
| 自动布局跟着变   | 图形变化后的回调（`editor.sideEffects`）                               | 自己写 Figma 自动布局算法                                    | ✅ 实测：5913 个自动布局 frame 里 5907 个和 Figma 摆得一模一样（§3.4） |
| 文字             | `canEdit`、`RichTextArea`（自带的 TipTap 富文本编辑器）、`textOptions` | Figma 文字和 TipTap 文档互相转换；改完重新量尺寸             | ✅ 查源码；重新量尺寸实测 2812 段文字里 2811 段行数一致（§3.5）        |
| 样式             | 可以换掉右侧的样式面板（`components.StylePanel`）                      | 自己做属性面板：填充、描边、圆角、阴影、字体、自动布局       | ✅ 查源码；自带面板只有 13 种颜色，用不了（§3.6）                      |
| 矢量形状         | 控制点（`getHandles` / `onHandleDrag`）                                | 改颜色：插件改成导出几何数据，按数据画；改路径点：工作量大   | 🟡 改颜色可行，改路径点建议先不做（§3.7）                              |

## 2. 怎么测的

- **查源码**：读 `node_modules` 里 tldraw 3.15.6 的源码（`tldraw/src/lib`、`@tldraw/editor/src/lib`），确认每个能力在这个版本里有没有、怎么接。
- **数据统计**：数一遍 `cases/` 里 64 个真实稿子页面（10 套社区稿子），一共 15027 个可见节点，看编辑会碰到哪些东西。
- **自动布局复现**：对 151 个用例里的每个自动布局 frame，只拿 frame 的设置和子图层的尺寸，按自己写的规则算出每个子图层的位置和尺寸，再和 Figma 实际给的 `absoluteBoundingBox` 比。误差超过 0.01 像素就算不一致。
- **文字重新量尺寸**：用 Playwright 打开 `/canvas?case=…&shot=1`，把每段自动尺寸的文字的 DOM 复制一份，不限宽度（自动宽度的文字）或者按原宽度（自动高度的文字）重新排版，量出来的尺寸和 Figma 给的比。151 个用例，2812 段文字。
- 统计和复现脚本都是一次性的，放在 scratchpad，没有进仓库。做自动布局时，§3.4 的对比会改成正式测试。

## 3. 逐项结果

### 3.1 真实稿子里有什么

64 个真实页面，15027 个可见节点：

| 节点类型  | 个数 | 节点类型          | 个数 |
| --------- | ---- | ----------------- | ---- |
| INSTANCE  | 4760 | GROUP             | 529  |
| FRAME     | 3725 | ELLIPSE           | 189  |
| TEXT      | 2890 | BOOLEAN_OPERATION | 55   |
| VECTOR    | 2212 | LINE              | 48   |
| RECTANGLE | 610  | COMPONENT         | 9    |

和编辑关系最大的几个数：

- **70% 的节点（10591 个）在自动布局里，文字更多，88%（2546 / 2890）。** 有 6339 个自动布局 frame，其中 10 个会换行。
- **64% 的节点（9603 个）在组件实例里面。** 主组件基本不在导出的页面里（只有 9 个 COMPONENT）。
- 文字：自动宽度 1921 段（66%），自动高度 801 段（28%），固定尺寸 167 段，截断 1 段。混合样式（一段文字里有不同字体或颜色）只有 55 段（2%），列表 2 段。
- 填充：纯色 6378 个，图片 672 个，线性渐变 192 个，径向渐变 74 个。有阴影或模糊的 443 个，有圆角的 2841 个。
- 矢量：2231 个 SVG，97% 只有一条路径，41% 带描边，带渐变的 4%，带图片的 2%。

所以**改文字时，自动布局一定要跟着重新排**。没有这一步，按钮里的字变长了，按钮不会变宽，字就跑到按钮外面，旁边的按钮也不会让开。

### 3.2 换成 tldraw 自带图形：不行

tldraw 的矩形、文字这些自带图形（`geo`、`text`）的样式只有几个档位（`@tldraw/tlschema` 的 `geoShapeProps`）：

- 颜色只能从 13 种里选（`DefaultColorStyle`），不能填任意颜色；
- 填充只有"无 / 半透明 / 实心 / 斜线"，描边粗细只有 s / m / l / xl 四档；
- 字体只有手写、无衬线、衬线、等宽四种；
- 没有圆角、渐变、图片填充、阴影、模糊、字间距、行高。

换过去以后，6378 个纯色会被凑到 13 种颜色上，图片、渐变、阴影和圆角都没了，现在 0.13% 的还原度也就没了。自带图形可以留给用户在画布上新画的东西，它们和我们的图形可以放在同一张画布上。

### 3.3 移动、缩放、旋转

- 现在 `apps/client/src/figma/shapes/base.tsx` 的 `FigmaShapeUtil` 把缩放、旋转都关了（`canResize` 返回 false，隐藏缩放和旋转手柄，见 [tech.md §3](tech.md#3-自定义图形2026-10-24)），只能移动。
- tldraw 缩放一个图形时，默认把子图形一起按比例缩放，像组一样；图形的 `canResizeChildren()` 返回 false 时子图形不动，自带的 frame 就是这样（`tldraw/src/lib/tools/SelectTool/childStates/Resizing.ts` 第 526 行）。
- Figma 的规则是：普通 frame 缩放时，子图层按各自的约束移动或拉伸（靠左、靠右、左右都贴、居中、按比例）；自动布局 frame 重新排；组按比例缩放。所以 `figma-frame` 要让 `canResizeChildren` 返回 false，在 `onResize` 里自己按约束摆子图层；GROUP 用 tldraw 默认的一起缩放。快照里普通 frame 的子图层都带 `constraints`：64 个真实页面里有 2710 个，其中 2073 个不是默认的"靠左、靠上"，所以这一步省不掉。
- 文字：拖宽度时，Figma 会把文字改成"自动高度"，拖高度时改成"固定尺寸"，我们照做。
- 矢量：现在是一整张 SVG，拉伸时描边会跟着变粗，要等 §3.7 改成按数据画才能保持描边粗细。
- 裁剪和组透明度的补法（`apps/client/src/figma/clip.ts`，[tech.md §5.1](tech.md#51-frame-裁剪)）本来就是按祖先的位置实时算的，拖动父图形时子图形会重新算，编辑后也照样对。
- 要注意：tldraw 3.15.6 里双击一个不能编辑的图形，会在那里新建一个 tldraw 文字（`SelectTool/childStates/Idle.ts` 的 `handleDoubleClickOnCanvas`）。要给 `figma-frame` 加 `onDoubleClick`，改成 Figma 的"双击进到里面一层，选中子图层"。

### 3.4 自动布局：能自己算，和 Figma 摆得一样

规则按 Figma 自动布局的设置来，和 CSS 的 flex 布局很像：

- 方向（`layoutMode`），内边距（`paddingLeft` 等），间距（`itemSpacing`）；
- 主方向的对齐（`primaryAxisAlignItems`）：靠前、居中、靠后、两端对齐；
- 另一个方向的对齐（`counterAxisAlignItems`）；
- 子图层的"填满"：主方向是 `layoutGrow: 1`，平分剩下的空间；另一个方向是 `layoutAlign: STRETCH`；
- "包住内容"的 frame（`primaryAxisSizingMode: AUTO`）的尺寸 = 子图层加间距加内边距；
- 绝对定位的子图层（`layoutPositioning: ABSOLUTE`）不参与。

151 个用例里有 6393 个自动布局 frame。去掉旋转过的 48 个、会换行的 12 个（这次没实现），再去掉 420 个没有子图层参与布局的，还剩 5913 个：

| 规则版本                                                                                           | frame 一致      | 子图层一致        |
| -------------------------------------------------------------------------------------------------- | --------------- | ----------------- |
| 第一版：方向、内边距、间距、对齐、填满                                                             | 5883 / 5913     | 10557 / 10594     |
| 再补三条：描边算进布局（`strokesIncludedInLayout`）、最小 / 最大宽高、两端对齐只有一个子图层时居中 | **5907 / 5913** | **10586 / 10594** |

剩下 6 个不一致：一个三等分的标签栏差 1/3 像素（Figma 可能做了取整）；两个"两端对齐只有一个子图层"的 frame，一个居中、一个靠前，原因没找到；一个子图层比父 frame 还高；一段文字差 0.17 像素；一个"包住内容"的 frame 差 5.8 像素。

还没验证的：

- 这次只验证了"一层"：子图层尺寸直接用 Figma 给的。真正编辑时，尺寸要从最里面一层往外算（包住内容），再从外往里分（填满）。做的时候要用 151 个用例整棵树重排一遍，结果必须和导入时一样。
- 触发时机：在 `editor.sideEffects` 里监听图形变化，自动布局里的图层尺寸、文字、显示隐藏变了，就重排它的父 frame，一直往上到不再变为止。重排放在同一次改动里，一次撤销就能全部退回去（未验证）。
- 拖动自动布局里的子图层：Figma 是调整顺序。不处理的话，拖完会被重排弹回原位，要在拖动结束时按位置算出新顺序。

### 3.5 文字编辑

tldraw 3.15.6 已经带了需要的东西，不用装新包：

- 图形的 `canEdit()` 返回 true，双击就进入编辑状态（`SelectTool/selectHelpers.ts` 的 `startEditingShapeWithLabel` 调 `editor.setEditingShape`）。
- 公开导出了 `RichTextArea`（TipTap 富文本编辑器）、`useEditableRichText`、`tipTapDefaultExtensions`；`<Tldraw textOptions={{ tipTapConfig }}>` 可以给 TipTap 加自己的扩展。

做法：

- **不编辑时**，照旧用现在的 `TextContent` 画（`apps/client/src/figma/shapes/figma-text.tsx`），还原度不变。
- **编辑时**，换成 `RichTextArea`，套上同样的字体、字号、行高 CSS。TipTap 文档从 Figma 数据转过来：按换行分段落，每段样式相同的文字是一个文字节点，带一个自定义的 `figmaStyle` 标记，里面放这段的样式。用户改完再转回 `characters`、`characterStyleOverrides`、`styleOverrideTable`。有了这个标记，以后还能选中几个字单独改颜色或字号。
- tldraw 自带的文字图形也用同一份 TipTap 设置，所以要在 `tipTapDefaultExtensions` 后面追加我们的标记，不能替换掉。

源码里发现一个坑：`RichTextArea` 发现传进来的 `richText` 和它上次发出的不是同一个对象，就会重新 `setContent`，光标会跳走（`tldraw/src/lib/shapes/text/RichTextArea.tsx` 开头的 `useLayoutEffect`）。如果每次渲染都从 Figma 数据重新转一份，打一个字光标就跳一次。编辑期间要把它发出来的那个对象原样传回去。

**改完以后的尺寸**：自动宽度和自动高度的文字，要按新内容重新量。用我们自己的画法量出来的结果：

| 文字     | 段数 | 宽度误差 ≤ 1 像素 | 宽度误差 ≤ 2 像素 | 行数一致     |
| -------- | ---- | ----------------- | ----------------- | ------------ |
| 自动宽度 | 1988 | 1853（93%）       | 1932（97%）       | 1988（全部） |
| 自动高度 | 824  | —                 | —                 | 823          |

宽度差得多的，主要是我们没有的字体：Product Sans 43 段里只有 21 段在 1 像素以内，Circular Std 49 段里 14 段，Proxima Nova、SF Pro 一段都没有。DM Sans 39 段里只有 14 段在 1 像素以内，差得最多的是一个大标题（642 → 628.8 像素），可能大字号时字体版本还有区别，未验证。只有改过的文字才重新量，没改过的继续用 Figma 给的尺寸，所以导入时的还原度不受影响。

### 3.6 样式：自己做属性面板

- tldraw 的样式面板只认 `StyleProp`（`DefaultStylePanelContent` 里一个个读 `DefaultColorStyle`、`DefaultFillStyle`……）。自定义 `StyleProp` 可以定义（`StyleProp.define`），但它必须是图形最外层的一个属性，而我们的样式都在 `props.node` 里面。为了用它把样式再抄一份出来，就有两份数据，迟早对不上。
- 建议：选中的全是 Figma 图形时，用 `components.StylePanel` 换成我们自己的属性面板，否则还是显示 tldraw 自带的。面板直接用 `editor.updateShapes` 改 `props.node`，撤销、重做都是 tldraw 管。
- 面板内容按 Figma 右侧栏来：填充（颜色、透明度；渐变和换图片可以晚一点）、描边（颜色、粗细、内外）、圆角、透明度、阴影和模糊、文字（字体、字重、字号、行高、字间距、对齐、大小写、下划线）、自动布局（方向、间距、内边距、对齐、尺寸方式）。选中多个图形、值不一样时显示"混合"。

### 3.7 矢量

- 现在矢量是插件导出的 SVG 字符串，颜色写死在里面（[tech.md §3](tech.md#3-自定义图形2026-10-24)）。64 个真实页面一共 2231 个 SVG、31.7 MB。
- 改颜色有两条路：直接改 SVG 字符串里的 `fill`、`stroke`（97% 只有一条路径，大多数能改对，但遇到渐变、蒙版就不好办）；或者让插件导出几何数据（`fillGeometry`、`strokeGeometry`，蒙版已经这样导了，见 [tech.md §5.2](tech.md#52-蒙版)），我们按数据画，和矩形用同一套填充、描边代码。建议走后一条，缩放时描边粗细也能保持不变。改完要重跑还原度对比，确认没变差。
- 改路径上的点：tldraw 的控制点（`getHandles` / `onHandleDrag`）能把点显示出来让人拖，但贝塞尔曲线的控制柄和 Figma 的矢量网络都要自己做，工作量大，建议先不做。

### 3.8 tldraw 版本

上面用到的东西 3.15.6 都有，`getShapeVisibility`（用来显示 / 隐藏图层）也有。4.x 多了 `getClipPath` 和 `BaseFrameLikeShapeUtil`，自定义 frame 可以直接裁剪子图形（[tldraw 文档](https://tldraw.dev/sdk-features/shape-clipping)）。但 4.0（2025-09）起正式环境必须有 license key（[License key](https://tldraw.dev/sdk-features/license-key)），开发环境不用。编辑用不到 4.x，建议留在 3.15.6。

### 3.9 没覆盖到的

- **组件和实例**：编辑的是页面里的一份拷贝，改一个实例不会影响别的实例，主组件也不在导出里。
- **隐藏图层**：现在转换时直接跳过 `visible: false` 的节点。想在 tldraw 里切换显示，要保留它们，用 `getShapeVisibility` 隐藏。
- **导出图片**：我们的图形没写 `toSvg`，tldraw 的导出和复制成图片应该是空的，未验证。
- **大页面的性能**：每打一个字都要量一次文字、重排一串 frame，最大的页面有几千个节点，未验证。

## 4. 对设计的建议

**保留自定义图形，在上面加编辑能力。** 按下面的顺序做，每一步都能单独跑起来、单独验收。每一步做完，151 个用例的还原度都要和现在一样，因为导入时的画法没变。

| 步骤 | 内容                                                               | 怎么验收                                                              | 工作量（估计） |
| ---- | ------------------------------------------------------------------ | --------------------------------------------------------------------- | -------------- |
| 1    | 打开缩放、旋转；frame 按约束摆子图层；组按比例缩放；双击进到子图层 | 约束的单测；手动拖几个 frame                                          | 小             |
| 2    | 自动布局：整棵树重排、改动后自动触发、拖动调顺序                   | 151 个用例整棵树重排后位置不变（§3.4 的对比变成测试）                 | 中             |
| 3    | 文字编辑：双击改字、改完重新量尺寸、触发自动布局                   | 2890 段文字转成 TipTap 再转回来完全一样；手动改按钮文字，按钮跟着变宽 | 中             |
| 4    | 属性面板                                                           | 改颜色、圆角、字号后画面对；撤销能退回                                | 中             |
| 5    | 矢量改成按几何数据画                                               | 还原度不变差；能改矢量颜色                                            | 中             |
| 6    | 可选：图层面板、隐藏图层、新建 Figma 风格图形的工具、导出图片      | 看需要                                                                | 看需要         |

要用户定的：

1. 走"保留自定义图形、加编辑能力"这条路吗？
2. 自动布局跟着变，算不算这次的范围？我建议算，不然改文字的体验很差。
3. 组件和实例先当普通 frame 处理（改一个不影响别的）可以吗？
4. 矢量改路径点先不做可以吗？
5. 改完写回 Figma，还是和交接文档一样不做吗？
