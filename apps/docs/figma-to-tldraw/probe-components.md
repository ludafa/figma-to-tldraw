# 调研：在 tldraw 里支持 Figma 组件

> 2026-10-25，tldraw 3.15.6，Node 26.12.1，macOS 27.0.1
> 起因：用户说「现在我们想要做一个 figma 组件的功能，要怎么做？首先是 figma 原有的组件体系，我们需要如何支持，其次是我们这边在 tldraw 体系里如何做映射？充分调研一下，给我一个报告。」
> 这份文档回答"Figma 的组件是怎么回事"和"在 tldraw 里怎么接"。用户定了方向以后，设计写进 [技术实现](tech.md)，步骤写进施工计划 [`docs/施工计划.md`](../../../docs/施工计划.md)。

## 1. 结论

**能做，不用换 tldraw 版本，也不用推翻"每个节点一个自定义图形"。** 实例里的每个图层仍然是一个真实的 tldraw 图形，照旧能选中、能画、能参与自动布局。在这个基础上加三样东西：

1. 主组件也变成图形，放在单独的"组件"页面里（§6.3）；
2. 实例记住自己用的是哪个主组件，以及自己改过哪些字段，也就是覆盖（override）（§6.2）；
3. 主组件一改，按"主组件 + 覆盖 + 组件属性"把每个实例重新算一遍，只把变了的图形写回去（§6.4）。

开源的 Penpot 就是这么做的，Figma 自己导出的数据也是这个形状（§5）。

**最大的缺口在插件：现在没导出主组件。** 151 个用例里有 5872 个实例，用到大约 500 个组件，导出的数据里却只有 10 个主组件、0 个组件集。没有主组件，就不知道实例里没改的部分原来是什么样，同步和切换变体都做不了。所以第一步是改插件，把主组件和整套变体导出来（§4.4）。

**Figma 的覆盖记录可信，但不全。** 同一个组件的最外层实例两两比较，有 7296 处样式不一样：7014 处写在 Figma 的覆盖记录里，剩下 282 处全是文字属性改的字，没有一处说不清（§4.3）。但嵌套实例从主组件带来的覆盖不在记录里，官方文档原话是 "Inherited overrides are not included"，这部分要拿到主组件才能算出来。

| Figma 的东西                       | 在 tldraw 里怎么做                                                               | 难度 / 依赖    |
| ---------------------------------- | -------------------------------------------------------------------------------- | -------------- |
| 主组件、组件集                     | 照旧是 `figma-frame`，`node.type` 是 `COMPONENT` / `COMPONENT_SET`，放在"组件"页 | 要先改插件导出 |
| 实例                               | `figma-frame`，`node.type` 是 `INSTANCE`，node 里带主组件 id、组件属性、覆盖记录 | 已有           |
| 实例里的图层                       | 照旧是真实图形；按路径（`I<实例>;<主组件里的 id>`）对应主组件里的图层            | 已有           |
| 覆盖                               | 实例上按"路径 → 字段名"记；用户改过就算，重置才清掉                              | 中             |
| 改主组件，实例跟着变               | 放进现有编辑引擎，和自动布局重排同一时机，撤销一步回去                           | 中             |
| 实例里不能做的事（挪、增删、换序） | 用 tldraw 的 before 回调拦下；删除改成隐藏                                       | 小             |
| 变体、布尔、文字、替换实例         | 属性面板加"实例"区块；切换就是换主组件 id 再重算                                 | 中             |
| 新建组件、生成实例、分离实例       | 改 `node.type`，复制主组件的子树                                                 | 小～中         |
| 实例里给图标换颜色                 | 矢量现在是 Figma 导出的整张 SVG，要先做第 9 步第 5 项"矢量按几何数据画"          | 依赖第 5 项    |
| Slots、库更新审阅、推回主组件等    | 先不做（§3.6、§7）                                                               | —              |

## 3. Figma 的组件体系

### 3.1 几个概念

- **主组件（main component）和实例（instance）**：主组件定义长相，实例是它的副本，主组件一改，实例跟着变。同一个文件里的改动立刻生效；别的文件要等组件库发布、对方接受更新以后才变。主组件只能在它所在的文件里改。
- **组件集（component set）和变体（variant）**：一组相似的组件放在一个组件集里，每个变体是一个普通组件，名字写成 `Size=Large, State=Hover`，表示它在每个变体属性上的取值。组件集里只能放组件。默认变体是左上角那个。
- **组件属性（component property）**：给实例用的开关，一共五种：

  | 类型            | 管什么                       | 备注                                   |
  | --------------- | ---------------------------- | -------------------------------------- |
  | `VARIANT`       | 选组件集里的哪个变体         | 只有组件集有                           |
  | `BOOLEAN`       | 某个图层显示还是隐藏         | 目前只能绑可见性                       |
  | `TEXT`          | 某段文字的内容               | 只能是纯文本                           |
  | `INSTANCE_SWAP` | 里面某个嵌套实例换成哪个组件 | 可以给一个推荐列表（preferred values） |
  | `SLOT`          | 一块可以往里放任意图层的区域 | 2026 年新加的，见 §3.6                 |

  属性改的是默认值时，只有没改过这个属性的实例会跟着变。

- **嵌套实例**：主组件里面又放了别的组件的实例，比如按钮里的图标。主组件可以把嵌套实例的属性"露出来"（expose），这样在外层实例的面板上就能直接改。
- **库组件（remote）**：从别的文件的组件库里来的组件，在当前文件里只读。

出处：[Guide to components](https://help.figma.com/hc/en-us/articles/360038662654)、[Create and use variants](https://help.figma.com/hc/en-us/articles/360056440594)、[Explore component properties](https://help.figma.com/hc/en-us/articles/5579474826519)、[Edit main components](https://help.figma.com/hc/en-us/articles/360038665934)。

### 3.2 实例里能改什么、不能改什么

| 能改（覆盖）                                           | 不能改（只有主组件能改）             |
| ------------------------------------------------------ | ------------------------------------ |
| 文字内容；字体、字重、字号、行高、字间距、自动尺寸方式 | 里面图层的上下顺序                   |
| 任意图层的填充、描边（类型、颜色、透明度）             | 里面图层的位置，包括自动布局里的顺序 |
| 阴影和模糊、布局网格、导出设置、图层名                 | 任意图层的约束                       |
| 显示 / 隐藏（在实例里按删除只是隐藏）                  | 文字图层的边框                       |
| 替换嵌套实例                                           | 增加、删除图层（Slot 除外）          |
| 实例本身的尺寸；自动布局的内边距和间距                 | 用缩放工具缩放实例里面的图层         |

- 里面图层的旋转、宽高能不能改，官方没写。论坛上 2021 年说不能，2026-08 有帖子说嵌套图标实例改宽高是可以的。**未确认。**
- **覆盖按字段记。** REST API 和插件 API 都给出 `overrides: [{id, overriddenFields}]`：每个改过的图层一条，列出改过的字段名。论坛上说覆盖是"粘住"的，手动改回原值也还算覆盖，要用"重置"才能清掉。这一点**未确认**。
- **主组件改了以后：** 实例里改过的字段保持自己的值，没改过的跟着主组件变。官方没有一句话直接这么写，这是从数据格式推断出来的；上面"属性默认值"那条规则是同一个意思。
- 实例的尺寸可以改，里面的图层按主组件上设好的约束或自动布局跟着变。

出处：[Apply changes to instances](https://help.figma.com/hc/en-us/articles/360039150733)、[Guide to auto layout](https://help.figma.com/hc/en-us/articles/360040451373)、[InstanceNode](https://developers.figma.com/docs/plugins/api/InstanceNode/)、[api-errors](https://developers.figma.com/docs/plugins/api/api-errors)。

### 3.3 切换变体、替换实例时，覆盖留不留

官方规则（[Apply changes to instances](https://help.figma.com/hc/en-us/articles/360039150733)）：

1. 图层名要对得上：当前实例里改过的图层，在新变体里要有同名的图层。
2. 这个属性在两个变体里原本要一样。比如红色变体的实例改成绿色，切到蓝色变体时，红和蓝本来就不一样，绿色就不保留，显示蓝色。
3. 文字放宽一点：名字对得上、层级差不多就保留。

从 Assets 面板拖着替换时只保留文字覆盖。插件 API 的 `swapComponent` 用的是和界面一样的规则，文档还说这套规则以后可能会改。

Penpot 基本照抄了这套规则，它的更新记录里有很多"切换变体后覆盖丢了"的修复，说明按名字配对很容易出错（§5）。

### 3.4 实例上的操作

| 操作               | 做什么                                                                              |
| ------------------ | ----------------------------------------------------------------------------------- |
| 分离实例（⌥⌘B）    | 变成普通 frame，长相不变，和主组件断开；对嵌套实例分离时，外面几层实例也一起分离    |
| 重置               | 重置某一项，或者"Reset all changes"全部重置；可以对整个实例，也可以只对里面某个图层 |
| 推回主组件         | 把实例上的改动写回主组件；主组件必须在同一个文件里，不能是库组件                    |
| 跳到主组件（⌃⌥⌘K） | 选中主组件；库组件会打开库文件                                                      |
| 删除主组件         | 实例都还在，面板上可以"恢复主组件"                                                  |
| 新建组件（⌥⌘K）    | 把选中的图层做成组件                                                                |
| 接受库更新         | 库发布新版后，文件里出现蓝点，可以全部更新、逐个更新，或者先对比再更新              |

出处：[Detach an instance](https://help.figma.com/hc/en-us/articles/360038665754)、[Create components](https://help.figma.com/hc/en-us/articles/360038663154)、[Update library assets](https://help.figma.com/hc/en-us/articles/360039234193)、[InstanceNode](https://developers.figma.com/docs/plugins/api/InstanceNode/)。

### 3.5 界面

- 组件和实例的选框是紫色的；组件集是紫色虚线框。
- 图层面板里，主组件的图标是四个菱形，实例是空心菱形。
- 选中：单击选外层，双击或 Enter 往里进一层，⌘ 单击直接选最里面。实例没有特别的规则，和普通 frame 一样。我们现在的选择逻辑已经是这样（[tech.md §13.1](tech.md)）。
- 右侧面板：最上面是组件名，点开可以换成别的组件；下面一个"属性"区块，变体是下拉框，布尔是开关，文字是输入框，替换实例是带图标的下拉框（推荐的排在前面），露出来的嵌套实例属性列在下面。"重置"和"推回主组件"在更多菜单里。
- "简化实例"（只显示部分属性）从 2026-03-23 起停用，以后所有属性和图层都显示。

出处：[Explore component properties](https://help.figma.com/hc/en-us/articles/5579474826519)、[Swap components and instances](https://help.figma.com/hc/en-us/articles/360039150413)、[Select layers](https://help.figma.com/hc/en-us/articles/360040449873)。

### 3.6 Slots（2026 年新功能）

- Schema 2025 上预告，2026-03-05 公测，2026-06-10 插件 API 更新日志写了正式上线（GA）。
- 主组件里的某个 frame 可以设成 slot。实例里可以往 slot 里加任意图层、调顺序、删掉，这打破了"实例里不能增删图层"的规则。slot 本身的位置、自动布局方向、约束还是由主组件管。
- REST API 的 25 种节点类型里没有 SLOT，slot 在导出数据里长什么样没有文档。**未确认。**
- 我们的 151 个用例都在 slot 上线前做的，数据里没有 slot。**建议这次先不做。**

出处：[Supercharge your design system with slots](https://www.figma.com/blog/supercharge-your-design-system-with-slots/)、[插件 API 更新 2026-06-10](https://developers.figma.com/docs/plugins/updates/2026/06/10/update/)、[SlotNode](https://developers.figma.com/docs/plugins/api/SlotNode/)。

### 3.7 数据长什么样

我们的插件用 `exportAsync({ format: 'JSON_REST_V1' })` 导出，格式和 REST API 一样。

- **实例**（`INSTANCE`）：frame 的所有字段，再加 `componentId`（主组件的 id）、`componentProperties`（每个属性的类型和当前值）、`overrides`（`[{id, overriddenFields}]`）、`exposedInstances`、`isExposedInstance`。
- **主组件、组件集**：frame 的所有字段，再加 `componentPropertyDefinitions`（属性的类型、默认值、变体的可选值、推荐列表）。
- **任意节点**：`componentPropertyReferences` 写这个图层的哪个字段绑在哪个属性上，比如 `{ characters: 'Heading#27:6' }`、`{ visible: 'Show icon#1:0' }`、`{ mainComponent: 'Icon#1:2' }`。
- **整个文件**：`components` 和 `componentSets` 两张表，写每个组件的 `key`、名字、是不是库组件（`remote`）、属于哪个组件集（`componentSetId`）。
- **实例里图层的 id**：`I<实例 id>;<主组件里这个图层的 id>`，嵌套时一层层往后接，如 `I108:9700;24:372;4:3458`。这个格式只在论坛上有说明，官方文档没写，但我们的数据里全是这样。
- **属性名**：布尔、文字、替换实例的属性名带 `#id` 后缀（`Heading#27:6`），变体属性不带（`Size`）。
- **插件 API**：在新的动态页面模式下，读主组件要用 `instance.getMainComponentAsync()`；`instance.overrides` 一样不含继承来的覆盖；`setProperties` 改属性；`swapComponent` 换组件并保留覆盖；`detachInstance` 分离。往实例里 `appendChild` 会报错 "Cannot move node. New parent is an instance or is inside of an instance"。

出处：[REST 节点类型](https://developers.figma.com/docs/rest-api/file-node-types/)、[REST 属性类型](https://developers.figma.com/docs/rest-api/file-property-types/)、[ComponentNode](https://developers.figma.com/docs/plugins/api/ComponentNode/)、[Working with component properties](https://developers.figma.com/docs/plugins/working-with-component-properties/)、[论坛：I 前缀的 id](https://forum.figma.com/ask-the-community-7/can-t-get-node-with-prefix-i-9560)。

### 4.2 已经有的

- 实例里的图层是 Figma 展开好的，现在导入就是照着画，所以还原度不受组件影响。
- 每个实例的 `componentId`、`componentProperties`、`overrides`，每个图层的 `componentPropertyReferences`，文件级的 `components` / `componentSets` 表，都已经在 `snapshot.json` 里。
- 现在的代码把 `INSTANCE`、`COMPONENT`、`COMPONENT_SET` 都当成普通 frame（`apps/client/src/figma/to-shapes.ts` 的 `SHAPE_TYPES`）。图层树里已经用了组件和实例的图标（`layers.tsx`），属性面板上显示"实例""组件"字样（`panel.tsx`），别的地方都没区分。

### 4.3 覆盖记录可信吗（实测）

**做法：** 同一个组件的最外层实例两两比较，每个实例最多和后面 7 个比，一共 6933 对、33358 对图层。比 34 个字段和文字样式（`style`）里的每一项，包括填充、描边、圆角、文字内容、自动布局设置、可见性和名字，不比位置和尺寸。规则如下：

- 一处不一样，要么这个字段写在任一边的覆盖记录里，要么是换了样式（填充样式 `inheritFillStyleId`、文字样式 `inheritTextStyleId` 等）。
- 里面的嵌套实例换成了别的组件，就跳过这棵子树（1365 处），因为这是替换实例属性的效果。
- 缩放过的实例跳过（172 对）。

**结果：**

| 项             | 数量                                               |
| -------------- | -------------------------------------------------- |
| 不一样的字段   | 7296 处                                            |
| 写在覆盖记录里 | 7014 处（96%）                                     |
| 文字属性改的字 | 282 处，全部是文字绑了 `TEXT` 属性，两边属性值不同 |
| 说不清的       | 0                                                  |

矢量另外比了 SVG。两边都没改颜色、尺寸也一样的矢量里：

- 1785 个 SVG 完全一样；
- 473 个只差小数点后的尾数（< 0.01）；
- 104 个只差 SVG 里自动生成的渐变 id；
- 13 个导出范围不同。

所以没被覆盖的矢量，直接拿主组件的 SVG 来用就行。

**导出里刚好有主组件的 4 个实例**，直接和主组件比：8 个图层、248 个字段，全部一致或写在覆盖记录里。

**发现的缺口：嵌套实例里的覆盖，有的不在记录里。** 例子：

- `furniture-e-commerce-community/design-product-detail-1` 里，`I108:8496;82:6625;24:400` 这段字是"Furniture"，主组件里是"Search something"。外层实例和嵌套实例的覆盖记录都是空的。
- 原因：这个改动是在外层实例的主组件 `82:6346` 里做的，属于"从主组件带来的覆盖"，Figma 不写进实例的覆盖记录。
- 所以拿嵌套实例互相比会有大量说不清的差异（第一次没区分最外层时，有几千处）。这部分只有拿到主组件，才知道哪些字段是主组件自己改的。

### 4.4 缺什么

1. **主组件。** 用到的 501 个组件只导出了 10 个。插件要对每个实例调 `getMainComponentAsync()`，把主组件导出来；主组件里的嵌套实例也要一路导下去。
2. **整套变体。** 主组件属于组件集时，要导出整个组件集，才能切到别的变体。现在数据里每个组件集最多用到 10 个变体，整套有多大**未测**。
3. **主组件里矢量的 SVG 和图片**，和现在导出页面的做法一样。
4. **隐藏的图层。** 布尔属性一打开，被隐藏的图层就要显示出来，所以导入时不能再跳过隐藏图层，要建成隐藏的图形（`getShapeVisibility` 已经支持隐藏，见 [tech.md §14.2](tech.md)）。插件导出 SVG 时也不能跳过隐藏的矢量。
5. **库组件能不能导出，未确认。** 库组件在文件里是只读的副本。对它调 `exportAsync` 行不行，要拿那 9 个库组件试一下。

## 5. 别的工具怎么存

| 工具                | 实例怎么找到主组件                                                          | 实例里的图层       | 覆盖怎么记                                                                       | 主组件改了怎么办                                                    |
| ------------------- | --------------------------------------------------------------------------- | ------------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Penpot（开源）      | 实例根节点存 `component-id`；每个图层存 `shape-ref`，指向主组件里对应的图层 | 真实存储，整棵复制 | 每个图层一个 `touched` 集合，按约 40 个"属性组"记（填充组、几何组、文字字体组…） | 显式同步：逐个属性复制，跳过 touched 的组；子图层列表做对比，增删挪 |
| Figma 内部（.fig）  | `symbolData.symbolID`                                                       | 不存储，算出来     | `symbolOverrides`：按图层路径记一小段字段                                        | 运行时重新算；`derivedSymbolData` 是算好的缓存                      |
| Figma 导出（REST）  | `componentId`                                                               | 展开好的           | `overrides: [{id, overriddenFields}]`，按字段                                    | 不适用（只读快照）                                                  |
| Sketch              | `symbolID`                                                                  | 不存储，渲染时算   | `overrideValues`，键是 `<图层 id>/<图层 id>_<属性>`                              | 渲染时套上，天然同步                                                |
| open-pencil（开源） | 每个复制出来的图层存来源的 id                                               | 真实存储（复制）   | 实例根节点上存 `instanceOverrides`：图层 id → 字段 → 值                          | 同步时跳过覆盖过的字段                                              |

几点值得借鉴：

- **两种存法各有用处。** Figma 和 Sketch 不存实例里的图层，每次用"主组件 + 按路径的覆盖补丁"算出来；Penpot 和 open-pencil 把图层真的复制一份存着。我们每个节点都是 tldraw 图形，只能走复制这条路。但同步时可以借 Figma 的思路：先用一个纯函数算出"实例应该长什么样"，再和现有图形比，只写不一样的。这样比 Penpot 那种一个属性一个属性地打补丁好测、也不容易漏。
- **配对用路径，不用 tldraw 的图形 id。** 图形 id 在复制、粘贴时会变。Figma 的 `I…;` 路径本身就是"主组件里的哪个图层"，正好拿来配对。
- **Figma 2026-03 重写了实例的底层**（博客 "How we rebuilt the foundations of component instances"）：旧的做法是任何改动都把整个实例重算一遍，换组件时编辑器会卡好几秒；新的做法只重算受影响的部分。我们的 Demo 先整实例重算，实例多了再优化。
- **Penpot 的坑**：切换变体丢覆盖的 bug 修了很多次，根子是按名字配对不稳。我们照 Figma 的规则做，但要准备一批切换变体的测试用例。
- tldraw 官方不打算内置组件。issue #1813 在 2024-07 关闭，作者说组件是"通往完整 Figma 功能的滑坡"，可以做成插件。官方示例里也没有现成的做法。

出处：

- Penpot 源码：[`types/component.cljc`](https://github.com/penpot/penpot/blob/develop/common/src/app/common/types/component.cljc)、[`types/container.cljc`](https://github.com/penpot/penpot/blob/develop/common/src/app/common/types/container.cljc)、[`logic/libraries.cljc`](https://github.com/penpot/penpot/blob/develop/common/src/app/common/logic/libraries.cljc)、[`logic/variants.cljc`](https://github.com/penpot/penpot/blob/develop/common/src/app/common/logic/variants.cljc)。
- Figma 格式的逆向实现：[fig2sketch `instance.py`](https://github.com/sketch-hq/fig2sketch/blob/main/src/converter/instance.py)、[open-pencil](https://github.com/open-pencil/open-pencil/tree/main/packages/scene-graph/src/instances)。
- Figma 博客：[How we rebuilt the foundations of component instances](https://www.figma.com/blog/how-we-rebuilt-the-foundations-of-component-instances/)。
- Sketch：[sketch-file-format](https://github.com/sketch-hq/sketch-file-format/tree/main/packages/file-format/schema)。

## 6. 在 tldraw 里怎么接

### 6.1 三条路

| 方案                                                              | 结论                                                                                                     |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| A. 实例里的图层是真实图形，实例记覆盖，改主组件时重新算一遍再写回 | ✅ 推荐。画法、选择、自动布局、文字编辑、属性面板、图层树全都不用改；导入时照 Figma 展开的画，还原度不变 |
| B. 实例是一个图形，里面直接画主组件                               | ❌ 里面的字和图层选不中、改不了，自动布局和文字编辑都要重写一套                                          |
| C. 实例只存覆盖，每次把里面的图形删掉重建                         | ❌ 图形 id 一直变，选中状态、图层树展开状态、撤销都会乱。它"重新算"的思路在 A 里用上                     |

### 6.2 数据怎么放

字段名照用 Figma 的，和"`props.node` 是唯一的数据来源"一致：

```ts
// 实例的 props.node（只列和组件有关的字段）
{
  type: 'INSTANCE',
  componentId: '438:1443',                  // 主组件的 node id
  componentProperties: { 'Property 1': { type: 'VARIANT', value: 'Favorite' } },
  overrides: [
    { id: '829:721', overriddenFields: ['width', 'height'] },        // 实例自己
    { id: 'I829:721;438:1442', overriddenFields: ['fills'] },        // 里面的图层
  ],
}
// 实例里图层的 props.node.id：'I829:721;438:1442'，分号后面就是主组件里对应图层的 id
```

- **覆盖记录要补全。** 导入时把"从主组件带来的覆盖"也算出来：拿主组件对比，找出主组件里嵌套实例改过的字段。补全后每个实例的记录都是完整的，后面同步只看这一份。
- **复制实例时要换 id 前缀。** tldraw 复制图形会把 `props.node` 原样带过去，复制出来的实例和里面的图层还是原来的 node id，覆盖记录也指着旧 id。复制和粘贴后，要把整棵子树的 node id 换成新实例的前缀。
- **主组件和组件集**照旧是 `figma-frame`。组件集里每个变体是一个 `COMPONENT`，`componentPropertyDefinitions` 在组件集或主组件的 node 上。

### 6.3 主组件放在哪

| 方案                                                       | 结论                                                                                                                                     |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 单独一个"组件"页面，导入时把用到的主组件和整套变体排在上面 | ✅ 推荐。主组件也是图形，用现有的画法和编辑功能就能改；"跳到主组件"就是切页面再选中；tldraw 一个文档本来就能有多个页面，撤销跨页面也能用 |
| 存在 `document.meta` 里，只当数据                          | ❌ 看不见，没法直接改主组件，还得另做一套编辑界面                                                                                        |
| 放在同一个页面上、画框外面                                 | ❌ 会出现在图层树和截图里，对比脚本的渲染范围要跟着改                                                                                    |

- 导出里本来就在页面上的 10 个主组件留在原处，和 Figma 一样。
- 库组件也放到"组件"页，但锁住、只读，和 Figma 一样（库组件只能在它自己的文件里改）。

### 6.4 改主组件时怎么同步

接在现有编辑引擎上（`apps/client/src/figma/editing/engine.ts` 的 `onChange` 和 `flush`）：

1. `onChange` 发现改动的图形在某个主组件里，就记下这个主组件。图形的增、删、挪顺序也算。
2. 操作结束时（`flush`，和自动布局重排同一时机），找出所有用到这个主组件的实例，包括嵌在别的实例里的。每个实例按下面的顺序算出里面每个图层应该是什么样：
   - 主组件；
   - 主组件里嵌套实例自己的覆盖；
   - 这个实例的覆盖；
   - 组件属性（文字、布尔、替换实例）。
3. 和现有图形一个个比，只写不一样的。主组件里加了、删了、挪了图层，实例里也跟着加、删、挪。
4. 写完后，现有的自动布局照常重排。以上都在同一次操作里，撤销一步就全回去。

要注意：

- **同步时写的改动不能被当成覆盖记下来**，要和自动布局重排一样，用引擎里已有的"暂停"开关（`withoutFigmaEffects`）。
- **主组件里套着别的组件时，要先算里面的。** 主组件 A 里有组件 B 的实例，改了 B，要先更新 A 里的那个 B 实例，再更新所有 A 的实例。还要防止组件互相套（A 里有 B、B 里有 A）。
- **不用 tldraw 的绑定（binding）把实例连到主组件**，直接用 `componentId` 查，见 §6.8。

### 6.5 在实例里编辑

| 用户做的事                         | 怎么处理                                                                                             |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 改实例里图层的颜色、文字、阴影等   | 照常改，同时把变了的字段名加进实例的覆盖记录。引擎重排、约束、文字重新量尺寸这些自动算出来的改动不算 |
| 改绑了文字属性的文字               | 改的是属性值，不记覆盖                                                                               |
| 拖动、缩放实例里的图层             | 拦下（Figma 不允许）。实例本身可以拖、可以缩放，缩放记成 `width` / `height` 覆盖                     |
| 删除实例里的图层                   | 改成隐藏，记 `visible` 覆盖（Figma 就是这样）                                                        |
| 往实例里画新图层、拖进图层         | 不让放进去：新建工具的 `dropTarget`（`create.ts`）跳过实例，6b 的"拖进 frame"也跳过                  |
| 在图层树里拖动调整实例里图层的顺序 | 不让拖                                                                                               |
| 双击、Enter 进到实例里面           | 现在就是这样，不用改                                                                                 |

拦截用 tldraw 的 side effect：

- `registerBeforeDeleteHandler` 返回 `false` 就不删；
- `registerBeforeChangeHandler` 可以把位置、父图层、顺序改回去；
- `registerBeforeCreateHandler` 可以改新图形的父图层。

这三个都在 tldraw 3.15.6 的 `@tldraw/store` 里（`StoreSideEffects.ts`）。

### 6.6 组件属性和变体

- **变体**：属性面板上每个变体属性一个下拉框。选了以后，在组件集里找属性组合对应的变体，把实例的 `componentId` 换过去，再按 §6.4 重算。覆盖按 §3.3 的规则保留：图层名路径对得上，并且这个字段在新旧两个变体里原本一样。
- **布尔**：开关。改绑定图层的 `visible`。
- **文字**：输入框。改绑定文字的 `characters`。
- **替换实例**：下拉框，推荐列表排前面。改嵌套实例的 `componentId`，再重算这个嵌套实例。
- **露出来的嵌套实例属性**：列在下面，改的是嵌套实例的属性。
- 改的都是实例上的 `componentProperties`，同步时按 `componentPropertyReferences` 套到对应图层上。

### 6.7 界面

- **紫色**：选中组件或实例时选框是紫色。tldraw 可以换掉 `SelectionForeground` 组件，按选中的是不是组件或实例换颜色。图层树里组件和实例的图标、名字也用紫色。
- **属性面板加"实例"区块**：组件名（点开能换组件）、属性、"跳到主组件"、"重置所有覆盖"、"分离实例"。主组件和组件集的区块显示属性定义。
- **"组件"页面**：左栏图层树上面加页面切换。
- **新建组件**（⌥⌘K）：把选中的 frame 改成 `COMPONENT`。**生成实例**：从"组件"页把主组件复制到画布上，得到一个实例。Figma 里复制粘贴主组件得到的是实例还是新组件，这次没查到官方说法，**未确认**。

### 6.8 tldraw 3.15.6 里要注意的

| 情况                                                                                                    | 怎么办                                                                                   |
| ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 不能加自定义的数据表（`createTLSchema` 只收 shapes、bindings、migrations；v5.0.0 才加了 `records`）     | 组件信息放在主组件图形自己的 `props.node` 里，不另建表，不用升级                         |
| 绑定（binding）只连两个图形；只复制实例、不带主组件时，绑定会被删掉；主组件里面的图形改了也不会通知绑定 | 不用绑定，用 `componentId` 找主组件；反过来"主组件 → 实例"的表用 tldraw 的 `computed` 算 |
| 复制、粘贴、⌘D 会原样复制 `props.node`                                                                  | 粘贴后换掉子树的 node id 前缀（§6.2）                                                    |
| side effect 一层套一层超过 100 层会报错 "Maximum store update depth exceeded"                           | 同步在 `flush` 里一次写完，不靠一层层触发                                                |
| 多人协作时，每个客户端都会各自同步一遍                                                                  | Demo 没有协作，先不管                                                                    |

## 7. 建议的步骤

每一步都能单独跑、单独验收，都不改导入时的画法，151 个用例的还原度要和现在一样。

| 步骤 | 内容                                                                                                                | 怎么验收                                                                                                   | 工作量（估计） |
| ---- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | -------------- |
| 1    | 插件导出主组件、整套变体、隐藏图层；导入时把主组件放进"组件"页；补全覆盖记录；写"主组件 + 覆盖 + 属性 → 实例"的计算 | 对 5872 个实例都算一遍，和 Figma 展开的比，除了浮点误差全部一致（像自动布局那样做成正式测试）              | 中             |
| 2    | 认出实例：紫色选框、图层树、面板上的组件信息、跳到主组件；§6.5 的编辑限制；改样式记覆盖；重置、分离                 | 单测：记覆盖、重置；手动：改实例里的字、删图层变隐藏、拖不动里面的图层                                     | 中             |
| 3    | 改主组件，实例跟着变，包括增删图层、调顺序                                                                          | 单测：改主组件后，没覆盖的跟着变、覆盖的不变；手动：改按钮主组件的颜色，页面上所有按钮跟着变，撤销一步回去 | 中             |
| 4    | 组件属性：变体、布尔、文字、替换实例、露出来的嵌套属性                                                              | 单测：切到某个变体后，和 Figma 里同一个变体的实例比；准备一批"切换后覆盖留不留"的用例                      | 中             |
| 5    | 新建组件、生成实例、新建组件属性                                                                                    | 手动                                                                                                       | 小～中         |

以后再说：Slots、推回主组件、库更新审阅、缩放过的实例（37 个，数值要乘缩放系数）、变量模式（现在的数据里没有）。

和第 9 步剩下的事的关系：

- **第 5 项（矢量按几何数据画）**：实例里 485 处图标换颜色要靠它。没有它，主组件里矢量的形状改了，换过颜色的图标没法跟着变。建议放在组件第 3 步之前。
- **6b（拖进别的 frame）**：要遵守 §6.5 的限制。先做 6b，组件第 2 步再加上实例的判断；先做组件，6b 写的时候就带上。哪个先都行。

1. 走 §6.1 的方案 A 吗？实例里的图层是真实图形，实例记覆盖，改主组件时重新算再写回。

## 9. 风险

| 风险                                                           | 应对                                                                                   |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 库组件能不能用插件导出，未验证                                 | 第 1 步先拿 9 个库组件试；不行就只读，用实例里展开的样子                               |
| Figma 没列全哪些字段能覆盖                                     | 以导出数据里出现过的 `overriddenFields`（68 种）为准；位置、顺序、约束按官方说的不让改 |
| 按图层名配对保留覆盖不稳（Penpot 修过很多次）                  | 照 Figma 的规则做，准备一批切换变体的测试用例                                          |
| 一个组件最多被用 560 次，改主组件时每个实例都要重算            | 先整实例重算，量一下耗时；慢了再改成只算受影响的图层                                   |
| 嵌套最深 6 层，从主组件带来的覆盖要一层层算                    | 第 1 步的正式测试覆盖全部 5872 个实例                                                  |
| 复制粘贴后 node id 重复，覆盖记录指错图层                      | 粘贴时换前缀；加单测                                                                   |
| 导入时开始保留隐藏图层，图层树、自动布局、截图对比都会多出东西 | 自动布局和组的边界已经跳过隐藏图层（tech.md §14.2）；跑一遍全量对比确认还原度不变      |
